ADIE — Automated Decision Integrity Engine

Formal verification of security decisions — with cryptographic proofs you can check in your browser.

What ADIE does

ADIE produces formal, independently auditable proofs for automated security decisions (approve, deny, execute, grant). Every decision is proven with Z3 SMT, signed with Ed25519, and rendered as a JSON manifest whose signature you can verify yourself — no server, no trust in us.

What’s verified here

Three claim classes are shipped as signed manifests. Each row corresponds to one JSON file next to this page.

ClaimFilesStatusManifest
P1213VALIDmanifest-P12.json
P1316VALIDmanifest-P13.json
P1432VALIDmanifest-P14.json

Each manifest is self-describing: it embeds the Ed25519 public key, canonical JSON (RFC 8785 JCS), SHA-256 hashes of every file, and one Ed25519 signature over the whole payload. Open index-v5.html to verify — or tamper with a byte and watch it fail.

Security posture

  • SBOM: CycloneDX 1.6, 61 components
  • Vulnerability scan: pip-audit + cargo-audit = 0 vulnerabilities
  • Signing: Ed25519 (dev keypair; production requires HSM/TEE)
  • Canonicalization: RFC 8785 JCS
  • Hash: SHA-256 per file, embedded in manifest
  • Negative tests: tampered + attacker-key fixtures shipped for demonstration

Verify independently

No trust in this site is required. The verifier is a single static HTML file — you can save it and open it offline. The manifests are plain JSON you can hash with sha256sum or verify with openssl pkeyutl -verify.
